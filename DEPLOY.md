# Emmaus AI — Deployment Checklist

## Before You Start

You need accounts for:
- [ ] MongoDB Atlas (free M0 cluster)
- [ ] Vercel (free tier)
- [ ] Render (free tier)
- [ ] Cloudinary (free tier)
- [ ] Langfuse (free tier)

You already have API keys for:

## Step 1: MongoDB Atlas (5 minutes)

1. Go to https://cloud.mongodb.com
2. Create free M0 cluster (any name; the application database remains `vedax` for compatibility)
3. Create database user (Database Access → Add User)
4. Whitelist all IPs (Network Access → Add IP → 0.0.0.0/0)
5. Get connection string: Drivers → Connect → Python → copy URI
6. Save as `MONGODB_URI`

### Create Search Indexes

After Atlas is ready, run:
```bash
cd apps/api
uv run python scripts/setup_search_indexes.py
```

Or manually in Atlas → Atlas Search → Create Index:
- Database: `vedax` (kept for compatibility with the existing application data)
- Collection: `document_chunks`
- Index name: `vector_index`
- Field: `embedding`, type: `vector`, dimensions: `1024`, similarity: `cosine`
- Filter: `workspace_id` (string)

Then create second index:
- Index name: `lexical_index`
- Field: `content`, type: ` Atlas Text`

## Step 2: Cloudinary (3 minutes)

1. Go to https://cloudinary.com and open your product environment.
2. In the left navigation, open **Developers → API Keys**.
3. Confirm the **Cloud name** matches `CLOUDINARY_CLOUD_NAME`.
4. Use an **Active** API key and copy its API Key and API Secret into:
    - Cloud Name
    - API Key
    - API Secret

5. The key must have permission for upload/create actions. If the key screen
   shows `Request forbidden` or `actions=["create"]`, click **Generate New API
   Key**, create a fresh key in the same product environment, and replace the
   Render values. Do not commit the secret.
6. Set `MEDIA_STORAGE=auto` to use Cloudinary with local fallback, or
   `MEDIA_STORAGE=local` if you do not want Cloudinary.

Emmaus now slugifies filenames and stops retrying Cloudinary after a permission
failure. A broken key will not break uploads: media is saved locally instead.
Cloudinary itself cannot be enabled by application code unless the dashboard
key has upload/create permission.

## Step 4: Deploy API to Render (5 minutes)

1. Go to https://render.com
2. New → Web Service → Connect GitHub repo
3. Select `Emmaus-AI` repo
4. Render auto-detects `render.yaml`

```

MONGODB_URI=mongodb+srv://<user>:<pass>@cluster0.xxxxx.mongodb.net/vedax?retryWrites=true&w=majority
MONGODB_DB=vedax
SECRET_KEY=<auto-generated>
CORS_ORIGINS=https://*.vercel.app,http://localhost:3000
MEDIA_STORAGE=auto
GROQ_API_KEY=your_groq_key
GROQ_BASE_URL=https://api.groq.com/openai/v1
GROQ_CHAT_MODEL=openai/gpt-oss-120b
GROQ_FAST_MODEL=openai/gpt-oss-20b
GROQ_VISION_MODEL=qwen/qwen3.6-27b
GROQ_STT_MODEL=whisper-large-v3-turbo
OLLAMA_API_KEY=your_ollama_key
OLLAMA_BASE_URL=https://ollama.com/v1
OLLAMA_CHAT_MODEL=gpt-oss:120b
OLLAMA_VISION_MODEL=gemma4:31b
EMBEDDING_PROVIDER=jina
EMBEDDING_API_KEY=your_jina_key
EMBEDDING_MODEL=jina-embeddings-v5-omni-small
EMBEDDING_DIMENSIONS=1024
CLOUDINARY_CLOUD_NAME=your_cloud_name
CLOUDINARY_API_KEY=your_cloudinary_key
CLOUDINARY_API_SECRET=your_cloudinary_secret
LANGFUSE_PUBLIC_KEY=your_langfuse_public_key
LANGFUSE_SECRET_KEY=your_langfuse_secret_key
SARVAM_API_KEY=your_sarvam_key
```

5. Deploy (takes ~3 minutes)
6. Note the URL: `https://emmaus-api-xxxx.onrender.com`

## Step 11: Telegram Bot (5 minutes, free forever)

The Bot API is 100% free with no usage charges.

1. Chat **@BotFather** on Telegram → `/newbot` → name it → copy the token
2. Generate a webhook secret (any random string, e.g. `openssl rand -hex 24`)
3. Set on Render: `TELEGRAM_BOT_TOKEN=<token>` and `TELEGRAM_WEBHOOK_SECRET=<secret>`
4. Register the webhook + command menu (one command, run anywhere with the API env):
   `uv run python scripts/set_telegram_webhook.py https://<your-render-api-host>/api/telegram/webhook`
5. Open your bot → `/start` → each Telegram chat auto-gets its own user + workspace

What users get: full multimodal chat (text, docs, photos, voice), `/new` /history /status /help, typing indicator, per-answer *Sources* + *New chat* buttons, and burst protection (8 msgs/min, one run at a time) so free-tier Groq quota is safe.

## Model Routing Summary

Fallback order: Groq → Ollama → Mock

| Task | Primary | 2nd | 3rd | Model |
|------|---------|-----|-----|-------|
| Reasoning (RAG, answers) | Groq | Ollama | Mock | openai/gpt-oss-120b |
| Vision (images, charts) | Groq (qwen3.6-27b) | Ollama (gemma4:31b) | Mock | qwen/qwen3.6-27b |
| Fast tasks (classify, rewrite, rerank) | Groq | Ollama | Mock | openai/gpt-oss-20b |
| Speech-to-Text | Deepgram | Sarvam | Groq | nova-3 / saaras:v4 / whisper |
| Embeddings | Jina | Local/Mock | — | jina-embeddings-v5-omni-small (1024D) |
